# MSA-GoFuture

Проект итогового спринта: целевая микросервисная архитектура платформы «GoFuture» для глобального масштабирования, обработки более 500 тысяч конкурентных поездок, динамического ценообразования, работы в нескольких регионах и запуска партнёрских решений.

## Структура решения

| Директория | Содержание | Основные артефакты |
|---|---|---|
| [Task1](./Task1/README.md) | Декомпозиция монолита на доменные сервисы | Нефункциональные требования, карта сервисов, очерёдность выделения, C2 To-Be, обратная совместимость, план миграции данных |
| [Task2](./Task2/README.md) | Event-driven архитектура | Модель доменных событий, схема топиков Kafka, Saga, механизмы надёжной доставки, C2 событийной платформы, мониторинг |
| [Task3](./Task3/README.md) | Глобальное развёртывание и отказоустойчивость | Выбор регионов, репликация, геомаршрутизация, failover, сценарии отказа, комплаенс, защита периметра |
| [Task4](./Task4/README.md) | Потоки данных, ML и BI | C4-диаграмма data pipeline от микросервисов до ML-платформы и BI, механизмы качества данных |
| [Task5](./Task5/README.md) | Мультитенантная платформа | Модель изоляции, IAM/SSO, автоматизированный onboarding партнёров, мониторинг арендаторов, матрица ролей |

## Ключевые архитектурные решения

1. **Декомпозиция по bounded contexts** вокруг доменов Booking, Driver, Pricing, Payments, Notification, Geography, Analytics и Fraud. Кросс-функциональные возможности — API Gateway, IAM, observability, event backbone — выделены в платформенные сервисы.
2. **Strangler Fig как основной шаблон миграции**: монолит постепенно оборачивается API Gateway, новые возможности разрабатываются в сервисах, существующие сценарии переводятся волнами без big bang.
3. **Событийная платформа на Kafka** с CloudEvents, Schema Registry, transactional outbox, idempotent consumers, DLQ и потоковой обработкой во Flink. Для жизненного цикла заказа используется orchestrated Saga.
4. **Регионально-ячеистая архитектура**: каждый географический регион содержит независимый data plane со всеми критичными сервисами. Глобальный control plane управляет конфигурацией, маршрутизацией, каталогами и деплоем, но не участвует в горячем пути поездки.
5. **Данные активной поездки обрабатываются в домашнем регионе пользователя/города**. Между регионами асинхронно реплицируются только справочные данные, конфигурация, обезличенная аналитика и данные, необходимые для DR.
6. **Data/ML платформа** строится на потоковом сборе событий, озере данных, ClickHouse для оперативной аналитики, Feature Store и ML pipeline для динамического ценообразования, прогнозирования спроса и антифрода.
7. **Мультитенантность** реализуется как гибридная модель: pooled-tenant для стандартных партнёров и dedicated-контур для крупных или регулируемых партнёров. Доступ контролируется централизованной IAM с OIDC/SAML SSO и атрибутно-ролевой моделью.

## Как смотреть диаграммы

Все диаграммы подготовлены в формате PlantUML с использованием C4-нотации и лежат рядом с соответствующими README в файлах `*.puml`. Для удобства проверки рядом также сохранены отрендеренные `*.svg`; они встроены в README соответствующих заданий и отображаются прямо в GitHub/GitLab без установки PlantUML.

Изменения, вносимые в глобальный ландшафт в задании 3, выделены на диаграммах красным цветом.
